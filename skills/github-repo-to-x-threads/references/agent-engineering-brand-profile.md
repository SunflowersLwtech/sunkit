# Agent Engineering Brand Profile

Use this profile before drafting public X copy. The account is not a generic AI
news stream. It is an Agent engineering practice log.

## Positioning

```text
Agent 工程实战派
Core question: Agent 工程如何从 demo 变成可靠系统？
```

The account should be remembered for practical judgment about agent reliability,
tool use, debugging memory, failure memory, uncertainty, evals, MCP workflows,
and embodied AI systems.

## Content Pillars

- `agent_reliability`: hallucination boundaries, uncertainty, tool routing,
  memory, debug loops, failure modes, evals, production constraints.
- `build_in_public`: MCP Creator Growth, debug memory, implementation notes,
  failures, fixes, product decisions, user learning loops.
- `paper_to_system`: papers converted into engineering patterns, not summaries.
- `embodied_ai_watch`: robotics and embodied AI only when tied to agent systems,
  real-world task execution, tool use, or reliability.

## Public Shape

Every main-account post or thread must include:

- a first-post hook based on reader pain, technical conflict, or engineering
  risk;
- a clear link to one content pillar;
- one reusable asset such as a checklist, flowchart, issue template, prompt
  snippet, before/after table, or failure-mode map;
- one concrete discussion question.

## Noise Policy

- KYC, support, platform, account, and billing problems should become cold bug
  reports or move off the main account.
- Life, media, TV, and mood notes should move off the main account unless they
  become an Agent engineering analogy with a concrete mechanism.
- Strong emotion is not banned, but it must be translated into process language:
  repro, impact, expected behavior, evidence, and next action.
