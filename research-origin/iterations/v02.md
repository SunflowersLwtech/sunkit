## Changes Made

### 1. Added Step 0: Prompt Type Detection
Before applying any lens, detect whether prompt is Diagnostic, Architecture, or Specification.
Spec prompts get light framework treatment — deliverable first, annotations second.

### 2. "Insight + Implementation" Hard Rule (Quality Standard #1)
```
BAD:  "The collaboration model IS the state."
GOOD: "The collaboration model IS the state — so initialize Yjs Y.Doc as 
       your single source of truth and let React subscribe to it."
```

### 3. "Organize, Never Filter" Hard Rule (Quality Standard #2)
When framework produces a unifying diagnosis, use it to GROUP findings, not DROP them.
All individual issues must still be enumerated under the umbrella concept.

### 4. Enumerate ALL Findings Rule (Code Review procedure)
Added explicit step: "If you detect 5 issues, report 5 issues."

### 5. Output Structure Guide
Added skeleton that ensures actionable core comes first:
```
[1-sentence diagnosis]
[Concrete recommendation — the ACTIONABLE core]
[Tacit rationale — WHY]
[All findings — organized, nothing dropped]
[What NOT to do]
```
