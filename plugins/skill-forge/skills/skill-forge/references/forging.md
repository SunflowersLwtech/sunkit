# 锻造法

一个 skill 只为一件事存在:在 agent 本会做错的决策点上改变它的行为。
每一段过删除测试:删掉这段,称职的 agent 在这个任务上还会做同样的动作吗?会 → 压舱物。

## 硬义务(每条可被第三方复跑核查,作弊即留痕)

1. 每个具体值三态可溯:本会话跑过 / 本会话核过 / 显式标 unverified。
   "X prevents Y" 形式的断言:测过,或删掉。
2. 引用的每个路径存在且含所说内容;指向空目录的指针比缺内容更糟。
3. 交付物存在且执行过;含脚本的必须真跑过。
4. frontmatter 解析:结构校验脚本直接跑,不解析的 skill 效应恒为零且静默。
5. description 分类器测试:写该触发与不该触发的真实措辞,逐条对描述文本核。
6. 发布前真实对比:同一 prompt 有/无 skill 各跑一次;输出相同 = skill 无效。
7. 退役一个源之前,先机械证明它的内容落了地;删源前列出未命中项逐条判。

## 判断指南(无法核查,只留判断)

- 测绘先于动笔:列任务阶段、失败的类、邻近案例、出错时谁受伤。
- 按决策点结构化;trap 写到野外可识别:长什么样、为什么有说服力、机制、动作。
- 绿灯要点名可观测量;停止条件写下来;分层按访问频率。
- 保鲜:会腐的事实带日期;规则被证伪就删,不追加反驳。
